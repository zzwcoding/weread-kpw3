# KPW3 部署前评审报告（插件 550741e + 设备端定制脚本）

评审时间：2026-08-14。基线：插件 main(92878ba) vs kpw3-enhance(550741e)；
设备脚本交叉核对：analysis/rootfs（官方固件 5.16.2.1.1，upstart 0.6.6，busybox 1.34.1）。

## 🔴 必须修

### 1. koreader.conf 用了 upstart 0.6.6 不支持的 `kill timeout`，整个 job 会被拒绝解析
- 文件：custom/files/etc/upstart/koreader.conf:15（kual-restore/koreader.conf:15 同样）
- 依据：rootfs initctl 字符串确认 upstart 版本为 **0.6.6**；`kill timeout` stanza 是
  Upstart 1.5 才引入的。rootfs/etc/upstart/ 全部 100+ 个 job **无一使用** `kill timeout`，
  0.6.x 遇到未知 stanza 会判定 job 文件解析失败并整体丢弃。
- 后果：koreader.conf 加载失败 → 开机自启完全不生效，且 framework 已被
  DONT_START_FRAMEWORK 拦下，设备可能停在无任何界面的状态。
- 修法：删掉该行（0.6.x 默认 TERM→5s→KILL 已够用）。可参考 kb.conf:13 已在用的
  `respawn limit 1 3600`（0.6.x 原生支持）。

### 2. 「重启进入原生系统」菜单的 Device:reboot() 在 Kindle 上是空实现，重启不会发生
- 文件：plugin/weread.koplugin/weread/ui/menu.lua:505-515
- 依据：KOReader upstream frontend/device/generic/device.lua:561 `function Device:reboot() end`
  是空桩；frontend/device/kindle/device.lua 未覆写 reboot，也未设置 canReboot。
  于是走"正在重启……"分支，0.5s 后调用一个 no-op。
- 后果：开关文件已删、提示"正在重启"，但设备不重启。
- 修法：Kindle 上 KOReader 以 root 运行，直接 `os.execute("reboot")`。

## 🟡 建议修

### 3. 缓存超限清理可能删掉刚下载完的书
- 文件：weread/ui/cache.lua:787-820（调用点 weread/lib/downloader.lua:1187）
- 按 mtime 升序清理可能删到本次刚保存的书或当前在读的书。
- 修法：清理列表排除当前活动下载/刚保存的 book_id。

### 4. 断点续传恢复的章节静默丢失脚注转换
- 文件：weread/lib/downloader.lua:752-776、1311
- dl.footnote_scans 仅存在于内存；resume 时跳过的章节脚注不转换也不回写。
- 可接受的降级，需在代码注释/README 注明。

### 5. koreader.conf 自停检查应移到 pre-start（官方惯例）
- framework.conf:6-17 把 DONT_START_FRAMEWORK 检查放在 pre-start，注释明确
  "check here so we don't engage respawning"。主 script 里 initctl stop 有理论竞态。

### 6. set -e 下失败会把 rootfs 留在 rw 状态
- 文件：custom/minimalize.sh、custom/restore.sh、custom/kual-restore/restore-autostart.sh
- 修法：`trap 'mntroot ro' EXIT`（busybox ash 支持 EXIT trap）。

### 7. kual-restore 的"警告后照常重启"分支可能开机卡死
- 文件：custom/kual-restore/restore-autostart.sh:33-40
- koreader.conf 缺失且副本也缺失时只警告就 reboot → framework 不起、KOReader 也不起。
- 修法：此情况下删除 DONT_START_FRAMEWORK（回原生系统）而不是直接重启。

### 8. 恢复/重装路径不清除崩溃计数文件
- restore.sh / restore-autostart.sh 应顺手
  `rm -f /var/local/koreader_last_start /var/local/koreader_start_count`。

### 9. 出厂重置 / locale 缺失时，禁用 pillow 会导致开机卡死
- langpicker.conf:110-133：locale 不存在时走 start_pillow 并无超时等待
  localeChange → langpicker_ready 永不发出 → 卡开机。
- 正常设备不受影响。README 需警示"恢复出厂设置前必须先跑 restore.sh"。
