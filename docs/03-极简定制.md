# 03 — 极简定制：禁用无关服务 + 开机直达 KOReader

目标：开机后**不经过原生界面**，直接进 KOReader；禁用一切与"KOReader + 微信读书"无关的原生服务。

## 原理

KPW3（固件 5.16.2.1.1）使用 upstart 0.6.6 管理服务，配置在 `/etc/upstart/*.conf`。精简不改任何文件内容，只做两件事：

1. **改名禁用**：把不需要的 `xxx.conf` 改名为 `xxx.conf.disabled`（upstart 只认 `.conf` 后缀）。改名前先复制到备份目录，`restore.sh` 可一键还原。
2. **官方开关禁用 Java framework**：`framework.conf` 的 pre-start 会检查 `/mnt/us/DONT_START_FRAMEWORK` 文件，存在则不启动。framework 不起，其下游（webreader/scanner/stored/dmld 等）全部不起。这是官方预留开关，零侵入。

## 自启 KOReader

`custom/files/etc/upstart/koreader.conf` 是自写的 upstart job：

- `start on started lab126_gui`——此刻 X/触屏/powerd/wifid/用户分区全部就绪，而 framework（被开关拦下）和原生阅读器（被禁用）尚未吃内存，是最干净的启动时机；
- 双开关：`/mnt/us/AUTOSTART_KOREADER` 和 `/mnt/us/koreader/koreader.sh` 都存在才启动（插电脑删掉开关文件即可回退原生系统）；
- **崩溃保护**：60 秒内第 3 次被 respawn 拉起时放弃（计数文件在 `/var/local/koreader_start_count`）。
  ⚠️ 这个保护在实践中经常被触发（比如 SSH 反复 stop/start KOReader 调试时），表现为 KOReader "起不来"。**排查时先删计数文件再 start**。
- 注意 upstart 0.6.6 兼容：不要用 `kill timeout`（1.5+ 的 stanza，0.6.x 会拒绝解析整个 job）。

## 禁用清单（minimalize.sh 当前版本）

| 分组 | 服务 |
|---|---|
| 原生阅读界面 | kppmainapp, kfxreader, kfxview, statusbar |
| OTA 后台 | otaupd, otav3（保留 ota-update.conf/otaup，手动刷包仍可用） |
| 遥测日志 | tmd, iohwlogs, printklogs, last_debug_info, phd（30秒心跳） |
| 亚马逊推送 | todo, maruinstall, wfmupdate, wfmdelete, wfm_forceupdate |
| 其他 | testd, sshd（系统自带 SSH；KOReader 的 dropbear 不受影响） |

**三个不能禁的（血泪教训，详见 docs/04、05）：**

- ❌ `demd`——`lab126.conf` 的启动条件是 `start on started system_setup_after_shpm and started demd`。禁了 demd → lab126（powerd/wifid/volumd 等）永不启动 → **卡开机动画、USB 无响应、电源键失灵，等于软砖**。
- ❌ `pillow`——系统屏保/休眠守护。禁了它合盖和电源键都不休眠。它在功能上依赖不深，但**休眠链必须有它**。
- ❌ 任何被其他 job `start on started xxx` 引用的服务——禁用前必须做反向依赖审计（grep 全部 conf 的 start on 条件）。

## 操作

从 KUAL 菜单执行 minimalize 扩展，或 SSH 手动：

```sh
sh /mnt/us/extensions/minimal/minimalize.sh   # 设备上路径以实际部署为准
```

## 回退

- 轻量回退：插电脑删 `/mnt/us/AUTOSTART_KOREADER` → 下次开机回原生界面；
- 完全还原：执行 `restore.sh`（改名恢复全部 .conf.disabled + 删开关 + 删 koreader.conf + 清崩溃计数）。

**红线**：恢复出厂设置前必须先跑 `restore.sh`——`DONT_START_FRAMEWORK` 状态下 OOBE（开机向导）会卡死。
