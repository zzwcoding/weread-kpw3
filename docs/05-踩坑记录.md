# 05 — 踩坑记录（复刻前必读）

按严重程度排序。每条都是实测踩出来的。

## 致命级（会变砖/功能死亡）

### 1. 禁服务前必须做反向依赖审计
upstart 的 `start on started X` 是硬依赖。把 X 禁了，所有等它的 job 永远不启动。
本案：`demd` 看似只是个遥测守护，但 `lab126.conf` 是 `start on started system_setup_after_shpm and started demd`——禁了 demd = 整个 lab126 层（电源/USB/WiFi/声音）死亡 = 软砖。
**方法**：禁用任何服务前，先 `grep -l "started 服务名" /etc/upstart/*.conf` 查所有下游。

### 2. pillow 是休眠链的必需品
`pillow`（pillowd）是屏保/休眠守护。禁用后：合盖不休眠、短按电源键无反应。它不参与启动依赖（所以依赖审计查不出来），是**功能依赖**。极简清单里不要包含它。

### 3. 无 framework 时电源键失灵的根因与修法
禁用 Java framework 后，`com.lab126.kaf` 服务名无人注册。powerd 每次收到电源键事件都去查 kaf 的 `frameworkStarted` 属性，查询失败 → 认为"开机动画还在" → **永久忽略电源键**（日志特征：`pbisplash: Splash screen is on. Ignoring power button`）。
修法：`custom/kafshim.koplugin` 用 liblipclua 注册一个最小 kaf 替身并注册属性 `frameworkStarted=1`、`splash=0`。
**liblipclua 注册属性的正确签名是 `handle:register_int_property("属性名", "rw", 初值)`**——参数里没有服务名（服务名就是 init 时那个），顺序错了不报错但属性注册不上，外部 `lipc-get-prop` 会得到 `lipcErrNoSuchProperty`。

### 4. 恢复出厂设置前必须还原定制
`DONT_START_FRAMEWORK` 状态下，OOBE（语言选择向导）起不来，恢复出厂会把设备卡在向导页。先跑 `restore.sh` 再做任何官方重置。

## 严重级（调试期高发）

### 5. KOReader 崩溃保护计数器会"假死"
自启 job 的保护逻辑：60 秒内第 3 次启动就放弃。调试时反复 `stop koreader / start koreader` 三次后，KOReader 就"再也起不来"了。
**解法**：`rm -f /var/local/koreader_last_start /var/local/koreader_start_count` 后再 start。所有 restore 类脚本都应自动清这两个文件。

### 6. KOReader 用户补丁的 device 中毒问题
`patches/1-*.lua`（早期补丁）在 `G_reader_settings` 初始化之前执行。此时补丁里 `require("device")` 会连带加载失败的子模块（gesturedetector 等），**把 device 模块毒化成"previous error"状态**，随后 reader.lua 正式加载 device 时直接崩溃，KOReader 起不来。
**解法**：需要碰 Device 的定制一律做成**插件**（plugins 在 device 就绪后才加载），不要用 1- 早期补丁。

### 7. KOReader 的 yes/no 约定是函数不是布尔
`canReboot = yes` 里的 `yes` 是 `function() return true end`。定制时写 `Device.canReboot = true`（布尔）会让 `Device:canReboot()` 报 `attempt to call a boolean value`，连锁炸掉 dispatcher 和所有插件加载。
**解法**：`Device.canReboot = function() return true end`。

### 8. 事件处理器注册时机
`UIManager.event_handlers.Reboot/PowerOff` 在 device 初始化时**按当时的 canReboot/canPowerOff 注册**。插件后改标志位不会重注册——处理器还是空操作，菜单点了没反应。
**解法**：插件里用 `UIManager:nextTick(function() ... 重新注册 ... end)` 在 UI 就绪后覆盖（参考 custom/powermenu.koplugin）。

### 9. 串口/USB 调试的四个 macOS 坑
多进程抢读乱码、波特率重枚举复位、跳线帽虚接、监听进程 fd 失效——详见 docs/04 第 2 节。一句话：**先回环测试，再动设备；全程一个读取者；监听掉了就重启进程**。

## 一般级

### 10. hotfix 版本要配对
PEKI 安装的 KUAL 依赖 KindleModding 通用 hotfix 2.5.0 的 `sh_integration`。刷 LanguageBreak 自带 hotfix 会导致 KUAL 菜单项点了没反应。

### 11. KOReader 的 SSH 服务器随休眠关闭
设备休眠后 SSH（2222 端口）即不可达；唤醒后 Wi-Fi 恢复但 dropbear 需要重新启动。调试脚本要考虑"设备可能睡着"。

### 12. KUAL 扩展格式
必须 `config.xml` + `menu.json`，且 menu.json 里用 `"action"` 字段写**绝对路径**。相对路径或缺 config.xml 都会让扩展不出现在 KUAL 菜单。

### 13. e-ink 残影会骗你
砖状态下"大树画面"可能是几小时前启动的残影。判断设备是否真重启：以串口日志或拔电池冷启动为准，别看屏幕。

### 14. upstart 0.6.6 的语法上限
`kill timeout` 等新 stanza 会导致整个 job 被拒绝解析。写 conf 只用的 0.6.x 已有官方用例的语法。

### 15. 时区永远跳回 UTC（无 framework 环境）
原生固件的 Linux 侧**不带时区数据库**（`/usr/share/zoneinfo` 只有 zone.tab，没有任何时区文件）——时区换算本来是 Java framework 干的。framework 禁用后：自动网络对时把系统时间同步成 UTC，手动改时间会被下次同步覆盖，且没有 tzdata 也无法本地换算。
**解法**（三步缺一不可）：
1. 从任意 Linux/macOS 拷 `/usr/share/zoneinfo/Asia/Shanghai` 到设备同路径（rootfs 需 mntroot rw）；
2. 再拷一份到 `/etc/localtime`（glibc 无 TZ 环境变量时的fallback）；
3. 写 `/var/local/system/tzVar`，内容 `KINDLE_TZ=Asia/Shanghai`（upstart env 会读）。
重启 KOReader 后时钟即显示北京时间，网络对时也会保持正确本地时间。
